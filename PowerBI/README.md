# Дашборд продаж розничной сети Соседушка
Руководитель сети хочет понять, что происходит с продажами.

## Задача
| Вопрос бизнеса | Аналитическая метрика / Разрез |
| :--- | :--- |
| **«Где растём / проседаем?»** | Выручка по месяцам, динамика YoY (Year-over-Year), срез по регионам |
| **«Какие магазины лучшие / худшие?»** | Выручка и средний чек в разрезе торговых точек |
| **«Помогают ли карты лояльности?»** | Сравнительный анализ среднего чека (с картой лояльности vs без карты) |
| **«Есть ли сезонность?»** | Помесячная динамика выручки, выделение пиков и провалов продаж |

## Данные
В качестве основы для анализа использовались исторические данные о продажах. Модель данных построена по классической схеме **«Звезда» (Star Schema)**.

* **Источник данных:** Excel-файл
* **Объем данных:** **80 000 продаж** за **2 года** наблюдений.
* **Структура модели данных:**
  * **Таблица фактов (Fact table):** Продажи (транзакции, чеки, количество, суммы, способ оплаты, % скидки).
  * **Таблицы измерений / Справочники (Dimension tables):**
    * 🛒 Магазины (география, даты открытия, площадь, форматы точек)
    * 📦 Товары (категории, бренды, подкатегории, себестоимость)
    * 👥 Клиенты (фио, пол, возраст, регион проживания, дата регистрации карты)
    * 📅 Календарь (дата, месяцы, кварталы, дни недели, выходные, YoY-периоды)
    * 🚚 Поставщики (наименования, города, профили поставки)

## Этапы реализации проекта
Разработка проекта велась по классическому циклу построения BI-систем и разделена на три ключевых технических этапа:
### 1. Подключение к данным (ETL: Extract)
* В качестве источника данных использован файл `Соседушка_данные.xlsx`.
* Настроено подключение к источнику через **Power Query**.
* Из файла через Навигатор импортировано **6 основных таблиц**, содержащих факты и нормализованные справочники (технический файл `README` был исключен из загрузки на этапе импорта).

### 2. Очистка и предобработка (ETL: Transform)
* Проведен аудит качества данных. Поскольку справочники изначально находились в чистом и структурированном виде, основной фокус был направлен на подготовку таблицы фактов.
* Выполнена предобработка и трансформация ключевой таблицы **`fact_sales`** (изменение типов данных, проверка на пустые значения, приведение данных к единому виду).
* *Примечание:* Учебная сырая таблица `fact_sales_dirty` была успешно отработана на этапе тестов и исключена из финальной продакшн-модели отчета.

### 3. Моделирование данных (Load & Data Modeling)
* На основе поля даты из таблицы `fact_sales` была динамически сгенерирована полноценная таблица **`dim_calendar`** (Календарь). Это гарантирует автоматическое расширение временных границ при добавлении новых продаж, непрерывность и предотвращает ошибки в расчетах time-intelligence.
* Спроектирована и построена классическая архитектура **«Звезда» (Star Schema)**.
* Центральная таблица фактов **`fact_sales`** была связана со всеми пятью справочниками:
  * `dim_products` (Товары)
  * `dim_stores` (Магазины)
  * `dim_customers` (Клиенты)
  * `dim_suppliers` (Поставщики)
  * `dim_calendar` (Календарь)
* Для всех связей проведена строгая валидация направления фильтрации: настроены связи типа **«один-ко-многим» (1:*)** от справочников к фактам, что гарантирует высокую производительность DAX-запросов.

### 4. Расчет бизнес-метрик (DAX-моделирование)
Для ответа на ключевые вопросы бизнеса был разработан комплекс DAX-мер. Все расчеты были оптимизированы и сгруппированы по функциональным блокам:
* **Базовые метрики эффективности (KPIs):**
  * `Выручка` — расчет общего объема продаж.
  * `Количество чеков` — оценка активности.
  * `Средний чек` — расчет среднего чека на одну транзакцию.
  * `Количество клиентов` — объем уникальной клиентской базы.
* **Анализ долей и сегментации:**
  * `Доля от общего` — расчет вклада конкретных категорий/регионов в общую выручку.
  * `Средний чек по карте` vs `Средний чек без карты` — изолированный расчет метрик для оценки эффективности программы лояльности.
* **Временной анализ (Time Intelligence):**
  * Таблица `dim_calendar` была официально размечена в Power BI как **Таблица дат (Mark as Date Table)** для корректной работы временных функций.
  * `Выручка YTD` — расчет выручки с начала года с нарастающим итогом.
  * `YoY %` — темп прироста выручки по отношению к аналогичному периоду прошлого года.

### 5. Проектирование интерфейса и визуализация данных
Каждый визуальный элемент дашборда был подобран строго под конкретную бизнес-задачу для обеспечения максимальной читаемости (Data Storytelling):
* **Блок верхнеуровневых KPIs:** Мультикарточки в шапке отчета (`Выручка`, `Кол-во клиентов`, `Средний чек`, `Кол-во чеков`,`Прирост YoY %`) для мгновенной оценки.
* * **Анализ сезонности и трендов (Продвинутая динамика):** Линейный график динамики выручки по месяцам, показывающий пики продаж и сезонные провалы, комбинированная диаграмма (столбцы + линии) в разрезе `Год-месяц`:
  * *Столбцы (основная ось):* Динамика `Выручки` для оценки абсолютных масштабов продаж.
  * *Линии (вспомогательная ось):* Метрики `YoY %` (сравнение с прошлым годом) и `Прирост к прошлому месяцу %` (MoM %) для мгновенного выявления скрытых аномалий, темпов роста и сезонных провалов.
* **Рейтинги (Top/Bottom):** Сгруппированные гистограммы в разрезе регионов и конкретных магазинов для выявления лидеров и аутсайдеров сети.
* **Оценка программы лояльности:** Столбчатая диаграмма (`С картой` vs `Без карты`), расположенные рядом для прямого сравнения и ответа на вопрос о влиянии карт на средний чек.
* **Структурный анализ:** Столбчатая диаграмма по категориям товаров для наглядной демонстрации структуры и концентрации продаж.
